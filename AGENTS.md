# AGENTS.md — Net Gongbu

Working rules for AI agents and new contributors. What the app does for the people who use it is
in `README.md` (English) and `README.ko.md` (Korean); this file is how the code is put together
and the rules for changing it. Why it is built this way, who it is for and what is still wanted
are in `INTENT.md`: read it before a change no rule here covers. The app is close to final for
now, so prefer small, contained fixes and ask before a large refactor or a new feature.

## What this project is

An **Electron desktop app** that teaches how a message travels through a network: hand-written or
measured scenarios play step by step over a 3D floor plan, a globe or a flat map, the packet of
each step can be opened as real bytes layer by layer, and a connected AI answers questions about
the screen or turns an answer into a new scenario.

The desktop installers are the only product (`913430f`): there is no server and no standalone
browser mode, and the viewer requires `window.lab`. Source and releases both live in the public
repo `magzogs/netgongbu`.

## Structure

```
packages/schema    topology and scenario schemas and validation, the AI draft format, globe coordinate conversion, locale (tr)
packages/trace     TraceReport (the measurement result), parsers for OS tools and DevTools events, measurement → map and scenario builder
packages/ai        scenarios from the connected AI, validation and fix-up retries, storage (ScenarioService, called by the desktop app)
packages/bridge    IPC contract between the desktop main process and the viewer (window.lab): channels, zod payloads, shared types
packages/protocols scenario packets → bytes encoded to spec, with field explanations (Ethernet·802.11·IPv4·ARP·ICMP·UDP·TCP·DNS·TLS 1.3·HTTP/1.1·HTTP/2·QUIC)
packages/llm       AI connections: ChatGPT (Codex app server, OpenAI API), Claude (Claude Code, Anthropic API), local LLMs; sign-in, keys, model lists, streamed answers
                   (the viewer imports only the types from "."; "./node" is called by the desktop main process)
apps/web           Vite + React + React Three Fiber viewer: the desktop app's screen (renderer)
  public/data      catalog.json, topologies/*.json, scenarios/*.json in Korean; the same names in English under en/ (trace-demo is generated by the builder)
apps/desktop       Electron app: app:// protocol, preload, laptop browser, measurement agent (src/main/trace), settings
  e2e              smoke.mts (test:e2e) and measure.mts drive the built app; screenshots go to e2e/out
media/             videos and stills for docs and promotion, and the one-off scripts that made them (media/README.md); not part of the app
```

Where the main flows live:

- **Measurement:** `apps/desktop/src/main/lab-browser.ts` (the laptop browser) → `trace/run.ts`
  (`local.ts` route/ARP/DNS settings, `dns.ts`, `traceroute.ts`, `enrich.ts` reverse DNS + ASN,
  `geo.ts` offline locations, `store.ts` history) → `packages/trace/src/build` (map and scenario).
- **AI scenarios:** `apps/desktop/src/main/ai.ts` → `packages/ai` (`prompt.ts`, `generate.ts`,
  `service.ts`) → `packages/llm/src/node` (one file per connection).
- **Packet anatomy:** `packages/protocols` (bytes and field explanations) → `apps/web/src/ui/lab`.

## Commands

```bash
pnpm install
pnpm dev                       # the desktop app (Electron): viewer + laptop browser + measurement + AI
NETGONGBU_FAKE_AI=1 pnpm dev   # canned AI answers, no connection needed (the first answer is wrong on purpose, to exercise the fix-up)
NETGONGBU_USER_DATA=<folder> pnpm dev   # a separate app data folder (settings, keys, measurement history, location DB)
pnpm check                     # lint (zero warnings) + format check + typecheck + tests; must pass before a commit
pnpm --filter @netgongbu/desktop test:e2e   # builds and launches the app, checks asking, measuring and packet anatomy (screenshots in e2e/out)
pnpm --filter @netgongbu/desktop measure -- example.com info.cern.ch   # measures for real with the built app, then takes screenshots
pnpm --filter @netgongbu/trace build:example   # rebuilds the trace-demo example (Korean and English) from test/fixtures/demo-report.json
pnpm --filter @netgongbu/desktop dist   # the installer for this computer's OS in apps/desktop/release/ (never publishes)
```

`measure` uses the build that `test:e2e` made. Options: `--download-geo` (download the location
database first if it is missing), `--open <measurement id>` (reopen a saved measurement), `--tour`
(play with the follow camera and take a screenshot every few seconds), `--user-data <folder>`
(defaults to the app's data folder, so the measurement history and the location database are
kept).

Tests are Vitest projects, one per package (`packages/*/test`, `apps/*/test`), run from the root.
The stand-ins for the `claude` and `codex` CLIs are in `packages/llm/test/fixtures` (run as separate
programs, so lint skips them), and the viewer's tests get a stand-in `window.lab`
(`apps/web/test/setup.ts`).

## Hard rules

1. **Desktop only** (why: `INTENT.md`). The viewer reaches the main process only through
   `window.lab` (preload + `packages/bridge`). Do not add HTTP clients, a server, or fallbacks for
   a missing `window.lab`.
2. **The main process holds the keys and sends every request.** It runs the CLIs and calls the AI
   APIs; the viewer never sees a key. API keys are stored encrypted with the OS keychain
   (`safeStorage`, `apps/desktop/src/main/settings.ts`); `OPENAI_API_KEY` and `ANTHROPIC_API_KEY`
   are read too. Never log a key.
3. **Claude accounts go through Claude Code.** Anthropic does not allow the OAuth tokens of Claude
   subscription accounts outside Claude Code and Claude.ai, so with account sign-in the questions
   are answered by Claude Code itself (`packages/llm/src/node/claude.ts`: `--safe-mode`,
   `--strict-mcp-config`, `--tools ''`, an empty working folder). Never read Claude Code's tokens
   to call the API directly. ChatGPT accounts go through the Codex app server
   (`codex app-server`, the one inside the ChatGPT desktop app is found too). `cliEnv` drops a
   surrounding Claude Code session's variables, so `pnpm dev` from inside Claude Code still talks
   to the user's own sign-in.
4. **Electron security stays on.** `contextIsolation`, `sandbox`, no `nodeIntegration` for the
   viewer and the laptop browser. IPC handlers are registered through `handle()` in
   `apps/desktop/src/main/ipc.ts`, which refuses any sender but the viewer (a page open in the
   laptop browser must never reach the main process); payloads are parsed with the zod schemas of
   `packages/bridge`. The laptop browser is an in-memory session with permissions, downloads and
   pop-ups blocked.
5. **OS tools run without a shell.** `execFile`/`spawn` with an argument array
   (`apps/desktop/src/main/trace/exec.ts`), `LC_ALL=C`, output parsed in
   `packages/trace/src/parse` (macOS, Linux). Host names come from the user and are never put into
   a shell string. The one exception is a Windows `.cmd` shim of an AI CLI (`spawnCli`).
6. **Privacy.** Router addresses are never sent to outside web services: locations come from the
   downloaded DB-IP database, operators from Team Cymru lookups over DNS. The measurement history
   stays in the app's data folder. `cookie`, `set-cookie`, `authorization` and
   `proxy-authorization` headers are masked (`SECRET_HEADERS`, `packages/trace/src/cdp.ts`).
7. **Every value says where it came from:** **Observed** (measured on this computer), **Derived**
   (computed from other values), **Typical** (a common value put in because it cannot be seen),
   **Spec** (fixed by the protocol). A value that cannot be measured is filled with a typical one
   and marked so, never shown as observed. Packets are not captured (that needs administrator
   rights); their bytes are built to spec from the measured values.
8. **Packets are encoded from the inside out** (`packages/protocols`). Lengths, checksums (the
   IPv4 header, TCP/UDP with the pseudo-header) and the Ethernet and Wi-Fi FCS (CRC-32) are
   computed from what is inside; frames under 64 bytes are zero-padded. DNS name compression, the
   TLS 1.3 ClientHello (SNI, ALPN, key_share), HPACK (static table, no Huffman) and the QUIC
   Initial follow the specs. HTTP/3 is built down to the QUIC 1-RTT packet; its frames are only
   described. Calls inside one computer (getaddrinfo …) put no bytes on a wire.
9. **The builder is deterministic** (`packages/trace/src/build`): the same `TraceReport` gives
   the same map and scenario. Locations are checked against the round trip
   (`build/geocheck.ts`): light covers about 200 km per ms in fibre, so a reply after r ms comes
   from within r × 100 km. A coordinate farther than that (anycast, a database error) is not used
   for placement, and the reason goes into the device's description.
10. **AI scenarios are validated, never trusted.** The system prompt bundles fixed instructions,
    the topology and example scenarios; the answer is structured output following the
    `ScenarioDraft` JSON schema (Claude API: `output_config.format` with prompt caching, OpenAI
    API: `text.format`, Codex: `outputSchema`, Claude Code: `--json-schema`). It is checked with
    `validateScenario`; the issues go back to the AI for a fixed scenario, up to 3 answers
    (`maxAttempts`, `apps/desktop/src/main/ai.ts`). A scenario uses only the devices on the
    current map. Making scenarios uses the same connection, model and Effort the user picked for
    asking.
11. **`packages/schema` is plain TypeScript and zod** (lint blocks `node:*`, `react`, `three`,
    `fs`, `path`): both the viewer and the main process import it.
12. **Two languages, Korean and English.** Every user-facing string is
    `tr('한국어', 'English')` from `@netgongbu/schema`, Korean first. The locale is one per
    process: the viewer picks it at startup and changing it reloads; the main process takes it
    from the viewer, and the AI answers in it. A hand-written example needs both
    `apps/web/public/data/…` and `apps/web/public/data/en/…` with the same file names.
13. **READMEs in both languages, everything else in English.** A README has an English and a
    Korean version (`README.md` and `README.ko.md`) that change together. Everything else written
    for people working on the code (`AGENTS.md`, `INTENT.md`, skills, code comments, commit
    messages) is English only, with no Korean copy. Korean in source files is for the app's own
    text (`tr`) and for quoting it.
14. **`pnpm check` passes** before a commit. A change in behaviour comes with a test beside the
    others in that package's `test/`.

## Writing scenarios

- A scenario is an array of beats (steps), and one beat can hold several hops (packets) that move
  at the same time.
- Every adjacent pair of nodes in a `path` must be joined by a topology link.
  `apps/web/test/data.test.ts` validates every file in `public/data` (not yet the English set in
  `public/data/en`).
- Split the hop at nodes where the headers change (NAT, MAC rewriting, proxies). If a hop with the
  same protocol and summary in the previous beat ended at that node, the inspector shows the
  changed fields next to their previous values.
- To add a scenario, add `scenarios/<id>.json` and register it in `catalog.json` (in both
  languages). Rebuild the measured demo with `pnpm --filter @netgongbu/trace build:example`.

## Releases

The installers are published as this repo's
[Releases](https://github.com/magzogs/netgongbu/releases). Never tag or push without being asked.

```bash
pnpm --filter @netgongbu/desktop dist   # builds the installer for this computer's OS in apps/desktop/release/ (does not publish)
git tag -a v0.2.0 -m "What changed…" && git push origin v0.2.0   # publish
```

Pushing a `v*` tag makes `.github/workflows/release.yml` build macOS (arm64 and x64 dmg), Windows
(x64 installer) and Linux (AppImage), and upload them to a release of the same name in this repo.
The version comes from the tag (the version in `package.json` does not need to change), the tag
message becomes the release notes, and a tag with a `-`, like `v0.2.0-beta.1`, makes a
pre-release. To redo a failed release, run Release in Actions again with the tag name; it
overwrites the files. The file names the README's download table lists come from
`apps/desktop/electron-builder.yml`.

Releases are uploaded with the default Actions `GITHUB_TOKEN`. macOS signing and notarization are
turned on with this repo's Actions secrets:

- `MAC_CERT_P12_BASE64` and `MAC_CERT_PASSWORD` (optional): a Developer ID Application certificate
  (.p12, base64) and its password. Without them the app is ad-hoc signed, and macOS asks for
  permission once, the first time it is opened.
- `APPLE_ID`, `APPLE_APP_SPECIFIC_PASSWORD` and `APPLE_TEAM_ID` (optional, together with the
  certificate): notarization.

## Commits

One change per commit, with a conventional prefix (`feat:`, `fix:`, `docs:`, `build:`,
`refactor:`, `chore:`) and a subject that says what the user now sees or what changed, in English
("feat: the left button moves the globe across the screen, as on the map; the right button turns
it"). The body explains why, and lists what followed (READMEs, package descriptions, lockfile).
